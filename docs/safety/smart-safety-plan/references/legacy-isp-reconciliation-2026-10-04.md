# Spec reconciliation: external ISP specification vs FabPilot repo (branch feat/governed-team-invitations)

Scope: read-only comparison. External spec = the ISP specification text (extracted from `ISP-Technical-Specification.docx`, ASML-EHS-IRL-PM-001, "Draft for approval", 30 Sep 2026). Repo = worktree `C:\t\p2x` (HEAD 82f1066, P2/SEL02 branch) with `origin/main` (local ref d074ac0, not re-fetched) used only for diffs. External line numbers refer to the ISP specification text. Repo paths are relative to `C:\t\p2x`.

## 0. Authority ladder: which source wins

- The repo has no rung for the external document. Its ladder is in `AGENTS.md` ("Documentation conflict resolution") and `.agents/skills/fabpilot-doc-reconciler/SKILL.md`: current owner direction and accepted ADRs establish intended behavior; code and executed tests establish observed behavior; proposals and low-trust docs do not override accepted decisions. `AGENTS.md` and `gap-resolution/README.md` also say "do not infer missing site authority, human approval or physical facts".
- ADR-0017 is not a document-authority ladder. It is about who may change metric specification limits (`Documentation/decisions/0017-...md` lines 23-31). It only helps by analogy: authority is expressed as explicit role lists, not rank. The real ladder reference is AGENTS.md plus the doc-reconciler skill.
- The external spec is a draft awaiting EHS Lead approval (external lines 17-19), so by the ladder it is a proposal. It states that it is "the authority the application is built and verified against" (line 22), but nothing in the repo records the owner adopting it. A grep for `ASML-EHS` / `ISP-Technical` in repo md/json found nothing.
- Therefore, on any direct conflict below, the accepted repo ADRs and owner rulings (W8-xx in ADR-0036, ADR-0039, SEL01-09 in the gap-resolution execution plan) win until the owner decides to adopt the external requirement. Where the external spec adds a requirement the repo has never ruled on, it is a candidate requirement, not a defect, and needs an owner/EHS Lead decision.
- Dates: ADR-0039 and the SEL selections (1-3 Oct 2026) are later than the external draft (30 Sep 2026).
- Caveat: the external spec describes a SharePoint-backed ISP/PTW app (section 15, `ISP_*` lists). The repo is a PostgreSQL/SQLite domain (ADR-0001). Section 15/16 and DATA-001..005 are not comparable one to one; I compared behavior only.

## (b) Decisions only the owner (or EHS Lead) can make

- D1. Is the external ASML spec adopted as normative for FabPilot? It is "Draft for approval" and describes a SharePoint implementation. Until adopted it is a proposal on the repo's ladder. If adopted, record it in an ADR and decide the precedence relative to ADR-0035/0039 and W8 rulings. Also confirm the glossary rule that external "L2/L3" are acknowledgement levels, not org levels.
- D2. Box handover gating (1.6/4.7): keep W8-38/43/50 (plan submission waits for box owner = action lead; accepting the box closes the approved plan) or change to external HND-005/CNT-004 (independent, never gates the ISP).
- D3. SRB carryover (4.6): keep W8-52/SEL05 conditional carry (P6) or follow SRB-002/CNT-003 (re-assess every new plan version).
- D4. Toolbox talk (4.8): keep record-only (W8-42a) or make it a gate (EXE-001).
- D5. New-plan prefill of people (2.3): which person is prefilled (current Task Lead vs previous plan lead), whether any "members" are carried, and fix the banner wording. Also whether to confirm the uncommitted test change to "Lena Lead".
- D6. Acknowledgement minimum (4.1): add "Action Lead plus at least one other named member" (ACK-005), or document that a single-person team is allowed.
- D7. L2/L3 leads and SRB (3.5): add L2/L3 to the Action Lead acknowledgement party, bar L2/L3 leads on board tasks, and/or add a separation-of-duties rule (distinct Action Lead, EHS, Team Lead).
- D8. Scope: which external-only modules to adopt (ACK Level 3 confirm-back, HND-002 key-count/lock verification, WoW floor and reasons, CON/GCN, EMG, EXE-007/008 closure statuses, PTW immutability/VOID details).
- D9. Title-to-role mapping (EHS Lead, Team Lead, Plant Manager, on-shift manager) onto L0-L9; the repo allows L9 as operational approver, external names Team Lead only.
- D10. Threshold storage (4.5): accept W8-57 (changing the threshold needs a migration) or make the band fully config-driven per PLAN-007.
- D11. Confirm enforce-at-submit for "plan must name the current Task Lead" (1.5) and record it in ADR-0039 and the model description; confirm draft save stays open.
